# SIGNAL / PLUGINS — бесплатный Telegram-дайджест

Этот проект ежедневно читает RSS-ленты, отбирает новости о VST-плагинах и аудиософте, удаляет уже опубликованные ссылки и отправляет подборку в Telegram.

**Стоимость:** 0 ₽ на GitHub Actions для небольшого проекта в публичном репозитории. ИИ на первом этапе не используется: фильтрация идёт по ключевым словам. Это позволяет сначала проверить качество источников и частоту публикаций.

## 1. Что понадобится

- Аккаунт GitHub.
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).
- Telegram-канал, где бот будет администратором с правом публикации.

## 2. Создать Telegram-бота

1. Открой в Telegram `@BotFather`.
2. Отправь `/newbot`.
3. Придумай имя и username бота.
4. Скопируй выданный токен. **Не публикуй его и не отправляй посторонним.**
5. Добавь бота в свой канал как администратора и разреши публикацию сообщений.

## 3. Узнать ID канала

Для публичного канала можно указать username в формате `@имя_канала`.
Для приватного канала потребуется числовой chat ID (обычно начинается с `-100`). Проще всего на первом этапе создать публичный канал или воспользоваться проверенным способом получения ID через Telegram Bot API.

## 4. Загрузить проект в GitHub

1. На GitHub создай новый репозиторий, например `vst-digest`.
2. Для простоты бесплатного запуска выбери **Public**.
3. Распакуй архив и загрузи в репозиторий все файлы и папку `.github`.
4. Проверь, что в корне видны `main.py`, `config.json`, `requirements.txt` и `state.json`.

## 5. Добавить секреты

В репозитории открой:

`Settings → Secrets and variables → Actions → New repository secret`

Создай два секрета:

- `TELEGRAM_BOT_TOKEN` — токен от BotFather.
- `TELEGRAM_CHAT_ID` — `@username` канала или числовой ID.

Токен хранится в Secrets и не должен попадать в код или `config.json`.

## 6. Включить GitHub Actions

1. Открой вкладку **Actions** репозитория.
2. Если GitHub предложит включить Actions — включи.
3. Найди workflow **Daily VST digest**.
4. Нажми **Run workflow**, чтобы проверить запуск вручную.

Расписание сейчас установлено на каждый день в 10:00 по Москве (07:00 UTC). Изменить время можно в `.github/workflows/daily-digest.yml` в строке `cron`.

## 7. Настроить источники и фильтрацию

Открой `config.json`.

- `sources` — список RSS-лент.
- `max_items` — максимум новостей в одном посте.
- `lookback_hours` — за какой период искать публикации.
- `relevance_keywords` — слова, по которым отбираются новости.
- `exclude_keywords` — слова, при наличии которых публикация исключается.
- `post_when_empty` — отправлять ли сообщение, если новостей нет.

Добавляй источники только с реальными RSS URL. Если лента перестанет работать, workflow покажет предупреждение в логах.

## 8. Как работает защита от дублей

После успешной публикации ссылки записываются в `state.json`. GitHub Actions сохраняет этот файл обратно в репозиторий. При следующем запуске ранее опубликованные ссылки пропускаются.

## 9. Важные ограничения первой версии

- Нет ИИ-перевода и ИИ-редактуры: это сознательно оставлено на следующий этап.
- Отбор по ключевым словам иногда пропустит релевантную новость или возьмёт лишнюю. Список ключевых слов можно улучшать.
- Если RSS-лента не указывает дату публикации, запись может попасть в дайджест, если она ещё не встречалась.
- GitHub Actions — не полноценный сервер. Для этого сценария ежедневного запуска его обычно достаточно, но расписание может запускаться с задержкой.
- В публичном репозитории нельзя хранить токены, пароли и приватные данные. Используй GitHub Secrets.

## 10. Локальный тест (необязательно)

Установи Python 3.11+, затем в папке проекта:

```bash
pip install -r requirements.txt
```

Linux/macOS:

```bash
export TELEGRAM_BOT_TOKEN="токен"
export TELEGRAM_CHAT_ID="@имя_канала"
python main.py
```

Windows PowerShell:

```powershell
$env:TELEGRAM_BOT_TOKEN="токен"
$env:TELEGRAM_CHAT_ID="@имя_канала"
python main.py
```
